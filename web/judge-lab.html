    03

    Use your own compiled contract

    The workspace inspects real WASM locally and exports a plan. Actual execution of custom WASM still requires the isolated Sandbox CLI.

    Go to contract workspace →
    RUN TESTS LOCALLY · FROM REPO ROOT
    cd sandbox
npm install --no-audit --no-fund
npm run build
node scripts/scan-contract.mjs --wasm build/protected.wasm --plan plans/settlement-protected.json --output protected.json
node scripts/scan-contract.mjs --wasm build/vulnerable.wasm --plan plans/settlement-vulnerable.json --output vulnerable.json

    The vulnerable command intentionally exits with code 1 because its state assertion fails; this is the expected finding in the example.

    Scope of evidence

    The reports originate from local NEAR Sandbox contract execution inside GitHub Actions, not NEAR mainnet or NEAR testnet. The hashes in these reports identify sandbox-local transactions, not publicly searchable network transactions. StateRift does not automatically detect unknown vulnerabilities in arbitrary contracts. This is an educational, reproducible failure-analysis case study, not a completed security audit.
